## 第十七轮 — StatusBar 冻结画刷崩溃修复 + Windows 10 兼容性

### Bug 修复

- [x] **StatusBar 冻结画刷动画异常** (System.InvalidOperationException)
  - **根因**: `StatusBorder.Background` 通过 `DynamicResource` 从主题资源字典获取的画刷在 WPF 中会被冻结（Frozen/Sealed），无法对其 `Color` 属性执行 `BeginAnimation`
  - **调用链**: `MainWindow.OnLoaded` try-catch 中调用 `StatusBar.Show(error)` → `Show()` 内 `StatusBorder.Background.BeginAnimation(ColorProperty, null)` 抛异常
  - **Windows 10 上必现**，因 Windows 10 冻结策略更激进

- [x] **修复方案**: 新增 `EnsureWritableBackground()` 安全方法
  - 检测 `IsFrozen`，若冻结则 `.Clone()` 替换为可写副本
  - 在所有 5 处 `BeginAnimation` 调用前插入该守卫：
    - `Show()` — 取消旧颜色动画
    - `CrossFadeText()` 回调 — 背景色平滑过渡
    - `ShowPersistent()` — 取消旧动画 + 颜色过渡回调
    - `FlashRed()` — 红色闪烁动画
  - 构造函数和 `ShowPersistent()` else 分支直接使用 `.Clone()` 赋值

- [x] **版本号** 1.0.12 → 1.0.13

## 第十八轮 — 日志系统全面升级 + Gitee 日志上传

### 背景

原有日志系统仅有 Trace.WriteLine + 每日文件写入，无日志级别、无结构化输出、崩溃日志写在桌面容易丢失、无法上传供远程排查。

### 需求

1. 结构化日志：Info / Warn / Error / Fatal 四级，含时间戳、组件名
2. 崩溃检测：自动写崩溃日志，弹窗询问是否上传（用户主动取消不算）
3. 手动上传：主界面右上角按钮，确认后上传
4. 上传目标：Gitee 私有仓库 `leaf-neko.-deploy-tool_-log` 的 `crash-logs/` 目录
5. 令牌编译进 DLL，用户无需配置
6. 不含第三方库

### 技术决策历程

1. 最初考虑 API 令牌 → 用户担心令牌有账户级权限
2. 转向 SSH + LibGit2Sharp（部署密钥仅绑一个仓库）→ 测试发现 Gitee 部署公钥只读，无法 push
3. 最终回到 API 令牌方案：令牌编译进 DLL，仓库只有日志，风险可控

### 关键设计点

- **取消判断**: `OperationCanceledException` 且 `CancellationToken.IsCancellationRequested` → 用户主动取消，不弹上传；递归检查 AggregateException 和 InnerException
- **崩溃日志**: 独立写入 `crash-logs/crash_YYYYMMDD_HHmmss.log`，含系统信息头 + 最近 100 条日志 + 异常堆栈
- **日志脱敏**: 上传前过滤 ≥32 位 hex 串 + `access_token`/`private_key`/`secret` 赋值语句
- **命名规范**: `deploytool_{run|crash}_v{版本}_{OS}_{时间}.log`
- **令牌安全**: 令牌作为常量编译进 LogUploadService.dll，不出现在 config.json 或任何日志中
- **待清理**: 之前的 SSH 密钥文件 `leafneko_log_upload*` 需在提交前删除
